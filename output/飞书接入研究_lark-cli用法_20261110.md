## 二、飞书接入路线（结论）

选型报告第五部分的原则不变：**飞书是业务数据源，不做全量复制；业务原始记录留在飞书，本地只存任务/授权绑定/审计/缓存元数据**。

落地分三层：

1. **身份层**：在目标公司租户创建自建应用，最小权限 scope，App Secret 只存服务端；`tenant_access_token` 按 `expires_in` 缓存（最长 2 小时）。把应用加为指定多维表格的协作者，否则查询返回空。
2. **工具层**：优先走 MCP/CLI 封装的领域工具（`base` 记录读写、`im` 通知、`docs` 报告沉淀），不要把飞书 API 散落到各 Agent 提示词里。
3. **治理层**：查询类工具 Allowed；写入类默认 Ask first（审批后再执行）；删除/批量/付款首期 Off。

### 与 ZCode 的结合点

ZCode 环境本身可跑 lark-cli（见下节），最自然的接入方式是：

- Agent（ZCode / Hermes 运行时）通过 lark-cli 或 feishu-business-mcp 读写飞书；
- 演示页面（`code/demo`）后续把静态合成数据替换为经 lark-cli 拉取的真实多维表格数据（服务端 serve.cjs 扩展为转发查询，页面仍不直接持有凭据）。

## 三、ZCode 里的飞书 CLI 怎么用（实测）

### 3.1 插件与 CLI 的关系

- ZCode 的 `lark-cli` 插件（`plugins/cache/zcode-plugins-official/lark-cli/0.1.2`）**只提供技能文档**（`skills/cli` 和 `skills/setup`），定义了 Agent 驱动 CLI 的安全规范；真正的命令行工具是官方 npm 包 **`@larksuite/cli`**。
- 本机安装情况：全局安装被拒（`D:\nodejs\node_global\node_modules` 对当前 shell 不可写，EPERM，沙箱外亦然），已按预案装到仓库隔离目录：

```bash
npm install --prefix tools/lark-cli @larksuite/cli@latest   # 1.0.99，已在仓库内
# 调用方式（任意目录）：
tools/lark-cli/node_modules/.bin/lark-cli.cmd <命令>
```

### 3.2 认证：两条路

**路线 A —— 绑定本机 Hermes 运行时（ZCode 集成路径，推荐先试）**

`lark-cli auth status` 实测返回 `not_configured`，且 hint 显示 **CLI 已检测到 `HERMES_HOME=C:\Users\admin\AppData\Local\hermes`**。说明本机 Agent 运行时已有飞书凭据，CLI 可直接继承：

```bash
lark-cli config bind --source hermes --identity bot-only   # 或 user-default
```

- `bot-only`：默认更安全，只以应用/机器人身份访问共享资源，不能碰个人日历/邮件/云盘。
- `user-default`：允许以用户身份代办（模拟用户），需要访问个人资源时才用。
- 规范要求：**必须先向用户确认意图和身份预设后再执行**；已绑定同一应用时改策略用 `config strict-mode` 而不是重新 bind。

**路线 B —— 独立 OAuth（不依赖 hermes）**

```bash
lark-cli auth login --scope <最小scope> --no-wait --json   # 拿 verification URL
lark-cli auth qrcode <url> --output qrcode.png             # 生成二维码给用户
# 用户完成授权后：
lark-cli auth login --device-code <device-code>
```

注意：README 记录过个人租户对 Base 类 scope 的组织级拦截；若仍被拒，回到既定方案——目标公司租户自建应用 + 管理员审批。

### 3.3 命令体系（Agent 快速上手）

```
lark-cli <domain> --help              # 发现领域命令；优先用 +shortcut
lark-cli base +record-search --help   # 每条 --help 标注 read|write|high-risk-write
lark-cli schema <service.resource.method>   # 调用前查参数、类型、scope
lark-cli api GET /open-apis/...       # 兜底：任意端点直接按 HTTP 路径调
lark-cli skills read lark-base        # 读内置领域指南（概念、命令选择、惯例）
```

实测要点：

- 22 个业务域：`base`(多维表格)、`im`、`docs`、`sheets`、`wiki`、`approval`、`task`、`calendar`、`contact`、`drive`、`mail`、`okr`、`vc` 等；内置领域指南 23 个（`lark-cli skills list` 可列出）。
- **`schema` 的服务名与域名不完全一致**：`schema base.record.list` 报 `Unknown service: base`（可用服务不含 base），base 域建议直接用 `+shortcut` 或 `lark-cli api` 兜底。
- 风险分级：`high-risk-write` 必须用户确认后加 `--yes`；写操作前先用 `--dry-run` 预览请求。
- 输出处理：`--jq <expr>` 过滤 JSON；**成功判定是退出码 0 且 `ok == true`**（顶层 `code == 0` 不可靠）。
- 默认显式 `--as user`；bot 身份必须用户明确指定，bot 缺权限走管理员开通，不能用用户 OAuth 修复。

### 3.4 典型最小链路（接入后第一天）

```bash
# 1. 确认身份与 scope
lark-cli auth status --json --verify
lark-cli auth check --scope <目标scope> --json

# 2. 只读验证：列指定多维表格的表
lark-cli base +table-list --app-token <token> --as user --format json

# 3. 读记录（查询类，Allowed）
lark-cli base +record-search --app-token <t> --table-id <id> --as user --jq '.data.items'

# 4. 写入（先 dry-run 预览，确认后执行；high-risk 需 --yes）
lark-cli base +record-create ... --dry-run
lark-cli base +record-create ... --as user
```

### 3.5 安全规范（来自 ZCode 插件 skill，Agent 必守）

- 发消息/建文档/改权限/写表格均为远端写操作：执行前展示目标资源、接收人、变更摘要并请求确认。
- 资源 URL/token/身份不明确时先问，不猜相似资源。
- 不输出 App Secret、OAuth Token、Cookie、本地配置内容；不让用户把 token 粘贴进聊天。
- 设备码过期就重发同范围流程，不复用旧链接。

## 五、决策记录（2026-11-10 更新）

- **凭据路径已定：方案 B——目标公司租户自建应用**（不走 hermes 绑定，不经个人租户授权）。
- **测试数据已定：使用现成的目标多维表格**做只读 PoC。
- 本机 CLI 部署形态：`tools/lark-cli`（npm 隔离安装，`@larksuite/cli@1.0.99`）；全局 `D:\nodejs\node_global` 不可写（EPERM）。
- 配置已有自建应用的命令形态（App Secret 走 stdin，不进聊天记录；hermes 上下文需 `--force-init`）：

  ```bash
  lark-cli config init --app-id <APP_ID> --app-secret-stdin --brand feishu --force-init
  ```

- Base 只读 scope 在开发者后台按「多维表格 → 只读」开通；确切 scope 串以 `lark-cli auth scopes` 与实际调用的 `missing_scopes` 报错（含 console_url）为准，不预猜。
- 自建应用必须被加入目标多维表格的协作者（文档应用/协作者），否则记录查询返回空（选型报告第五部分第 1 条已引用官方 FAQ）。
- 后续 PoC 步骤：`auth status --verify` → `auth scopes` → `base +table-list --app-token <t> --as bot` → `base +record-search`。数据身份读共享业务表用 `--as bot`（应用身份）。
